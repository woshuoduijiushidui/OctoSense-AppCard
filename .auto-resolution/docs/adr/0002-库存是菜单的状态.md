# 库存是菜单的状态，而不是接受菜单的门槛

#5 要求菜单在满足饮食限制和阶段目标的前提下优先使用库存，并把不足的部分变成缺菜清单。原先 `validate` 把「每种食材都有未过期且足量的批次」当作接受菜单的硬门槛，模型也被要求只使用库存内食材，于是缺菜在结构上不可能出现，模拟补齐无从开始。现在接受菜单只校验饮食限制、营养目标与周期热量额度；库存是否足够降级为每个食材项的状态（足够 / 缺 N g），由缺菜清单承接。

**Status**: accepted

## Considered Options

- **库存作为接受门槛（原状）**：菜单永远可执行，但缺菜与模拟采购无从产生，#5 的需求 1–4 无法实现。
- **库存作为状态（已选）**：一个「菜单」概念同时覆盖「库存可满足」与「需要补齐」两种情形，缺菜由同一次比较派生；代价是接受菜单不再保证可立即执行，界面必须把差距显示出来。
