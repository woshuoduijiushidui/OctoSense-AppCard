# 冰箱管家 (pantry-steward)

本地优先的饮食管理应用。用户建档后选择并组合健康方案，按当前阶段目标与冰箱库存生成菜单，确认实际食用后更新摄入与库存。

## Language

### 方案与计划

**健康方向**:
用户建档时选择的饮食目标倾向，例如减脂控卡、健身增肌、健身减脂。只用于推荐候选方案，本身不可执行。
_Avoid_: 方案, 计划

**周期**:
一份方案的时长天数，取值为 1、3、7、15、21、30 天。
_Avoid_: 阶段, 计划, 执行期

**方案**:
针对某个健康方向与周期生成的候选执行方案，带有该周期的营养目标（热量、蛋白质、纤维、维生素 C）。确认之前它只是候选。
_Avoid_: 周期, 程序, 菜单

**阶段**:
一份已确认的方案的快照，在计划中占据一个位置并承担该位置的起止日期。阶段的起止日期开始之日即锁定：之后不可调整顺序、替换、移除或改目标，因此修改未来阶段不会影响已确认的记录。
_Avoid_: 周期, 方案

**计划**:
按顺序排列的若干阶段组成的长期执行序列，例如 7 天＋15 天＋30 天共 52 天。总天数由各阶段的周期相加得出，不单独设定。
_Avoid_: 方案, 周期, 方案组合

### 执行与进度

**实际执行记录**:
用户确认过的每餐实际食用内容与数量。它是进度与库存消耗的唯一依据；生成或确认菜单都不产生实际执行记录。
_Avoid_: 菜单记录, 计划记录

**进度**:
已完成餐次数除以应完成餐次数（周期的天数 × 每日餐次，当前每日餐次为 3）。按阶段计算，计划进度为各阶段之和。已获得的进度不会因修改未来阶段而改变。
_Avoid_: 完成率, 达成度
