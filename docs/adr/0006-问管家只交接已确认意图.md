# 0006 问管家只交接已确认意图

状态：Issue #3 PR review 修正，2026-10-13

## 决定

问管家对菜单生成或调整只提出一段可编辑的 `goal` 要求。用户在菜单页核对并确认后，调用现有 `online_plan_ready()`；Issue #5 菜单流程读取当时的档案、阶段和库存，生成完整三餐候选，经本地校验后展示。用户还要在菜单页接受候选，接受前不扣库存。

问管家提案保留日期、档案、库存、阶段和已接受菜单的状态快照。状态变化或今日已有实际食用记录时，意图失效。模型生成的菜单内容不作为已确认要求传递，也不能绕过 Issue #5 的候选生成与接受动作。

库存提案继续进入 Issue #2 的草稿和确认流程；实际食用描述继续进入 Issue #6 的核对流程。过敏与忌口来自当前档案，是硬限制。普通偏好仅在用户明确要求记住、候选通过校验且菜单最终接受后，才可作为软记忆保存；当前明确指令优先于软记忆。

## 原因

确认的是用户的要求。三餐明细由菜单模块在确认之后按最新业务状态重新计算，使 Agent 对话与菜单分配、营养校验和最终接受共用一条执行路径。
